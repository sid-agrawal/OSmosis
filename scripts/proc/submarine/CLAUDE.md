# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in the submarine directory and the broader OS modeling system.

## Overview

This directory contains the **submarine** component of the OS modeling system - specialized tools for isomorphic search and graph analysis within process/memory models. The submarine tools work with graph data extracted by the main OS modeling system to identify structural patterns, relationships, and security-relevant configurations.

## Submarine Directory Components

### Core Submarine Files

- **isosearch.py**: Primary isomorphic search engine for finding structural patterns in OS models
- **scenarios.py**: Predefined search scenarios and pattern definitions
- **bfs_search.py**: Breadth-first search utilities for graph traversal
- **graph_transformations.py**: Graph manipulation and transformation utilities
- **generic_model.py**: Generic graph model representations
- **test_bfs_search.py**: Test suite for BFS search functionality

### Analysis and Session Management

- **conversation_progress.md**: Session progress tracking for complex analysis tasks
- **session_context.md**: Context preservation for ongoing analysis sessions
- **todo.json** / **todo_list.json**: Task management for submarine operations

### Output and Visualization

- **plos.html**, **plos_ind.html**, **ploss.html**: HTML reports and visualizations
- **sosp.pdf.html**, **sosp.pdf_ind.html**, **sosp.pdfs.html**: PDF-based analysis reports

## Submarine Usage Patterns

### Running IsoSearch

Always activate the virtual environment first:
```bash
source .venv/bin/activate
```

Run a named scenario (greedy search, default 10 iterations):
```bash
python3 isosearch.py <scenario_name>
```

Run with more iterations (needed for multi-goal scenarios like privsep):
```bash
python3 isosearch.py privsep --max-iterations 30
```

Run quietly (compact per-iteration output):
```bash
python3 isosearch.py privsep --max-iterations 30 --quiet
```

Available scenarios: `mediation`, `privatization`, `sharing`, `privsep`, `cache_partitioning`, `crypto_cache_isolation`

Key flags:
- `--max-iterations N` — override iteration count (default 10; use 30 for privsep)
- `--quiet` — suppress verbose metric dumps, show per-iteration summary only
- `--beam-search` — use beam search instead of greedy
- `--beam-width N` — beam width for beam search (default 12)

### Graph Analysis Workflow
```bash
# Perform BFS analysis on graph data
python bfs_search.py --input <csv_data> --target <pattern>

# Apply graph transformations
python graph_transformations.py --transform <type> --input <graph_file>
```

## Key Submarine Concepts

### Isomorphic Search
- **Pattern Matching**: Find structural equivalents of known security patterns
- **Scenario-Based**: Use predefined scenarios for common security analysis tasks
- **Graph Isomorphism**: Identify functionally equivalent but structurally different patterns

### Search Scenarios
Defined in `scenarios.py`:
- **Isolation Violations**: Patterns indicating broken isolation boundaries
- **Privilege Escalation**: Structural patterns that enable privilege escalation
- **Resource Sharing**: Identify unexpected resource sharing patterns
- **Namespace Violations**: Detect namespace boundary violations

## Development Guidelines

### Adding New Search Scenarios
1. Define pattern in `scenarios.py`
2. Add corresponding test in `test_bfs_search.py`
3. Update isomorphic search engine in `isosearch.py`
4. Generate test data using parent system tools

### Submarine-Specific Testing
```bash
# Run submarine test suite
python test_bfs_search.py

# Validate scenario definitions
python scenarios.py --validate

# Test isomorphic search with known patterns
python isosearch.py --test --scenario all
```
